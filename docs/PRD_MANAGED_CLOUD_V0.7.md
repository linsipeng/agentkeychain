# AgentKeychain Managed Cloud v0.7 PRD

- 状态：开发基线
- 权威版本：v0.7
- 目标用户：已经使用 AI Agent、担心凭证泄露和越权的个人与小团队
- 产品形态：仅 AgentKeychain 官方托管云
- 基线：AgentKeychain v0.6.2

## 1. 产品定义

AgentKeychain Cloud 是 AI Agent 的凭证权限与交付基础设施。用户只需要理解：**Agent 可以安全使用凭证，但看不到、带不走长期秘密。**

### 1.1 核心结果

1. 用户登录一次后，多设备自动同步，无需执行 push/pull。
2. AI Agent 请求普通读取时可按最小权限自动执行。
3. 发布、付款、删除、修改权限必须由用户确认。
4. 云端永远不保存可直接使用的明文凭证。
5. 用户可通过平台账号验证发起恢复，不因忘记本地主密码永久失去全部数据。

### 1.2 唯一产品模式

只提供官方托管云服务。用户界面、文档和默认命令不得再要求用户：

- 拥有 Cloudflare 账号；
- 安装 Wrangler；
- 创建 D1/Worker；
- 复制 Worker URL；
- 管理共享 Sync Token；
- 理解 BYO Cloud 或自托管。

### 1.3 最高优先级安全与隔离红线

- secret value、master password、设备私钥、Vault Key 和长期 KEK 不得以明文进入云端、聊天、Prompt、日志、遥测、崩溃报告或 Git。
- 云端同步对象必须端到端加密，并由设备签名；服务器不得伪造合法客户端版本。
- 每台设备使用独立身份和可独立吊销凭证，不允许所有设备共享一个长期 bearer token。
- 恢复不能由单一应用服务静默完成；必须拆分账号验证、受控密钥重包裹、用户通知和审计证据。
- 删除必须同步 tombstone，旧设备不得复活已删除凭证。
- 冲突采用服务器最后接收版本作为当前版本，但所有被替代密文必须进入历史版本，禁止静默销毁。
- 任何破坏上述红线的实现，即使功能测试通过，也不得合并、部署或发布。

## 2. 首发用户与场景

### 2.1 用户

- 个人 AI 重度用户；
- 2–10 人使用 AI Agent 的小团队；
- 已在本地、服务器或多个 Agent 中使用 API Key、部署 Token、邮箱、云平台凭证；
- 不愿把长期凭证粘贴给 AI，也不愿维护自建云服务。

### 2.2 首个闭环

1. 用户安装 AgentKeychain 并登录官方账号。
2. 本机生成设备密钥对，设备注册到账号。
3. 用户通过 Secure Capture 保存凭证。
4. 本地立即加密保存，并自动将签名密文同步到云端。
5. 第二台设备登录后，经账号验证与设备批准获得加密的 Vault Key 包。
6. AI Agent 请求使用凭证；读取类动作按最小权限自动执行，高风险动作弹出确认。
7. 所有访问、同步、批准、拒绝、设备吊销和恢复事件可审计。

## 3. 同步规则

- 服务端为每次接受的写入分配单调递增 `server_sequence`。
- 同一 secret 的当前版本为服务器最后接受的合法签名版本。
- 客户端重试必须携带幂等键，同一请求不得产生多个版本。
- 删除写入 tombstone，并与普通版本一样分配 sequence、签名和历史。
- 拉取以 sequence 游标为准，不依赖客户端时钟。
- 被替代版本进入历史记录，默认至少保留 30 天。
- 客户端离线修改后恢复连接，按服务器接收顺序决胜；产品不要求用户解决日常冲突，但允许从历史版本恢复。

## 4. 身份与密钥模型

- Account：官方账号身份。
- Device：每台设备独立公私钥和设备凭证，可单独吊销。
- Vault Key：随机生成，不直接等同于用户密码。
- Device Key Package：Vault Key 分别加密给每台获批设备。
- Recovery：账号验证通过后进入受控恢复流程；具体密钥重包裹必须是独立安全边界并产生通知与审计。
- Agent Identity：本阶段定义接口，不完成团队级机器身份后台。

## 5. 风险审批

### 自动执行

- 在已授权 scope 内读取凭证并注入本地受信进程；
- 查询凭证是否存在、健康状态和非敏感元数据；
- 自动同步和版本拉取。

### 必须确认

- 对外发布；
- 付款、购买、转账；
- 删除凭证或版本；
- 修改 scope、成员、设备、Agent 权限；
- 导出、恢复、轮换和扩大访问范围。

审批必须绑定请求摘要、Agent 身份、目标动作、凭证引用、有效期和一次性 nonce，禁止批准后替换请求内容。

## 6. v0.7 实现范围

1. Sync Protocol v2 数据结构与服务端 sequence。
2. 幂等写入、拉取游标、tombstone 和历史版本。
3. 独立设备身份模型、注册/吊销契约和签名验证接口。
4. 自动同步状态机与离线重试队列。
5. 风险动作分类及审批请求数据契约。
6. Managed Cloud 配置取代 BYO Cloudflare 用户入口。
7. v0.3 本地配置兼容检测和安全迁移提示，不自动上传或泄露旧 Token。
8. 中英文文档同步更新。

## 7. 本阶段不做

- 正式生产部署和域名；
- 真实支付、计费和公开注册；
- 企业 SSO/SCIM；
- 浏览器密码自动填充；
- 团队组织后台；
- 自动迁移现有 Vault 或修改生产 Keychain；
- GitHub Release。

## 8. 验收否决项

以下任一成立即判定失败：

- 测试或同步访问生产 Vault/Keychain；
- 云端或日志出现明文 secret、master password、私钥、Vault Key；
- 删除无法跨设备传播或旧设备可复活删除项；
- 共享长期 Sync Token 仍作为新用户默认身份；
- 用户仍需要部署 Cloudflare Worker/D1；
- 使用客户端时间作为唯一冲突顺序；
- 高风险动作可绕过确认；
- 恢复可以由单一服务无审计静默执行；
- 现有 v0.6.2 Vault 兼容性被破坏。
