## One acceptance route

1. **Offline, before asking for access:** On one exact commit, use the actual isolated installed entrypoint, original protected device identity, pinned Auth/Main/Custody, and pilot-only native state. Deliberately lose the commit reply. Resume with the same package and identity, get fresh Custody proof, read back both protected state and SQLite, then terminate and restart. Show **waiting for approval** before approval, **not active** while proof or local finalization is missing, and **active** only after fresh proof and durable agreement. On cancellation, expiry, revocation or mismatched state, do not activate or sync. These describe required behavior, not existing CLI strings.
2. **Hosted, after the runtime is ready:** Use the [staging execution card](CONTINUATION_PILOT_STAGING_EXECUTION_CARD.md). Record exact commit, origins and RP ID, named Workers, fresh per-role D1 IDs, operators, migration hashes and disable-first rollback. Obtain one concrete owner decision on the disposable scope and teardown; independently verify ownership and noncollision. Same-account Cloudflare demonstrates functional separation, not independent administration. Physical passkey registration and explicit approval are separate ceremonies, performed only on the verified isolated Auth page.
3. **Extend that same hosted run:** Activate a second installed device, exercise signed sync, authorization/revocation, and independent recovery. Record exact commit/artifact digests, migration versions, timestamps and safe error categories with `pass` / `fail` / `not run` for each gate. Do not capture tokens, cookies, raw assertions, private keys or Vault plaintext; never reuse or reset an existing Vault. On failure or expiry, disable new ingress first and tear down only approved disposable resources.

Keep migrations 0024/0025 and Worker cleanup compatibility together. Retained retirement/successor rows are intentionally protected; an older Worker can attempt to delete them during routine cleanup. Verify a rollback-compatible Worker or use fresh disposable databases. Do not remove retention guards or roll back a live database ad hoc. Roll out browser cookie changes with matching static assets; see the [cookie rollout notes](BROWSER_SESSION_COOKIE_ROLLOUT.md). Do not merge, deploy or publish based on fixture results alone.
